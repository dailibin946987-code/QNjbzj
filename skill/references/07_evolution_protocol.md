# 进化护栏协议（自我进化）

> 来源：LY_剧本大脑 技能改造机制 + LY_监察者 锚点体系通用化。进化必须在护栏内进行：先快照、后沙箱、经门禁、再晋升；失败回滚。

## 一、触发条件
1. 审核/监察报告中**同一问题出现 ≥2 次** → 判定结构性缺陷。
2. 监察者上报"技能反复触犯同一锚点"。
3. 用户主动指出功能不好用/某规则不合理。

## 二、进化流程（六步护栏）
1. **上报与归属**：记录问题现象（含复现案例）→ 判定归属层（创作流程/审核规则/台词规则/记忆规则/本包协议）。
2. **根因分析**：定位导致错误的规则/流程/模板条目；比对历史错误案例确认非偶发。
3. **快照冻结**：记录当前生效版本号与关键规则摘要（冻结基线，防修改失控）。
4. **隔离推演（沙箱）**：在草稿区起草新规则；用旧错题用例回放验证新规则能覆盖触发问题，且不破坏其他门控。**期间不动生效文件。**
5. **门禁判定**：通过条件 = 新规则覆盖触发用例 ✓ + 不回退已锁定锚点 ✓ + 六维/门控无回归 ✓。
6. **晋升/回滚**：通过 → 写入生效规则，版本 +0.0.1，通知监察者复检，evolution log 记录；失败 → 丢弃草稿保持原版，记录失败原因（连续 2 次失败停止自动进化，请用户人工决策）。

## 三、安全约束
- skill/ 知识源为"只读"，一切修改必须走本流程；禁止绕过门禁直接改规则。
- 单次只改一个根因；批量问题逐项走流程（禁止合并授权）。
- 涉及本包协议层修改时，须同步更新 SKILL.md 对应章节与版本号。
- evolution log 只增：记录每次尝试（成功与失败）供回溯。

## 四、进化记录格式
每条含：trigger（触发问题与次数）/ root_cause / draft_rule / replay_result（错题回放）/ verdict（晋升/回滚）/ version（+0.0.1）/ timestamp。

## 五、与监察者闭环
进化晋升后 → 监察者复检新规则 → 复检通过则错题本对应条目更新为"已由规则修复" → 记忆官记 validated 经验；复检失败 → 回滚并告警。
